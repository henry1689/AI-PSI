# ADR-0022：ProposalGate 权威边界（阶段 6.5 §二.13–15）

- **状态**：已接受
- **日期**：2026-09-18
- **相关**：ADR-0005（策略不得自动生效）、ADR-0018（反馈、经验与提案）、
  ADR-0019（阶段 6 独立评审）、ADR-0020（经验评价与独立性语义）

## 背景

阶段 6 的提案生成链路上，门槛**只被计算了一次**，算完把结果
（一个布尔 `PromotionDecision.allowed`）往下传给生成器与落库方。

阶段 6 的独立评审（ADR-0019）确认了它的后果：

> 一个手工构造的 `PromotionDecision(allowed=True)` 加上一条经验的模式
> 就能生成提案——"第二道保险"只是一句转发。

阶段 6 当时的修法是让 `ProposalGenerator` 多问两遍
（"裁决列出来的触发条件，证据撑得起吗？"）。那是**在消费端打补丁**：
它挡得住"触发条件与证据不自洽"，挡不住"证据本身就是过期的"
或"这一批证据从来就没有达到过门槛"。而且它是 Python 里的一行代码——
**任何能构造 `PromotionDecision` 的调用方都可以绕过它。**

阶段 6.5 §二.13–15 要求的不是更严的校验，是**换一个信任模型**。

---

## 决策

新增 `ai_psi.application.proposal_gate.ProposalGate`。
落库之前，门槛由它**从存储重新查询、重新计算**。

```
事件流（真相）
   ↓  重新查询
ExperienceReader.load()
   ↓  重新计算
PatternDetector.detect()  →  只取这一个键
   ↓  重新裁决
PromotionPolicy.decide()
   ↓
GateVerdict
   ↓  必须携带
ProposalService.create()
```

### 1. 输入里没有 `PromotionDecision`

`ProposalGate.review()` 只接受 **`error_type` + `situation_signature`**
（"要看哪个键"）与一组非模式的观测输入（`GateEvidence`）。

🔴 **§二.14 因此是结构性成立的，而不是一条注释。**
调用方无法把"我已经算过了"告诉门禁——**它根本没有那个参数**。

这一点值得展开：能靠"删掉一个参数"满足的要求，就不该靠
"调用方要自觉"。前者在代码评审、重构、以及每一个新调用点上都
自动生效；后者在第一个赶时间的下午就会失效。

### 2. `GateVerdict.authorised` 是**算出来的属性**，不是构造参数

```python
@property
def authorised(self) -> bool:
    return (
        self.pattern is not None
        and self.decision is not None
        and self.decision.allowed
        and self.pattern.weighted_count >= self.threshold
    )
```

"结论说可以、证据说不行"这种状态**不存在**——它没法被构造出来。

最后一项（加权计数不低于门槛）在前两项成立时是冗余的。
它被显式写出来，因为它是整个门禁**唯一真正要回答的问题**：
将来有人放宽前两条中的任何一条时，这一条仍然会拦住不达标的证据。

### 3. 构造凭据（以及它**不**是什么）

`GateVerdict.__post_init__` 检查一个模块私有的哨兵对象，
对不上就抛 `InvalidRequestError`。

🔴 **这不是密码学意义上的防伪——Python 进程内没有那种东西。**
`object.__new__`、`dataclasses.replace` 之类的路都还在。
它的作用是让"随手构造一个结论然后往上填数"**立刻炸掉**，
而不是安静地生效；深挖它需要写下明显可疑的代码，
而那正是代码评审该拦住的东西。

真正的防线是第 2 条：即使绕过了凭据检查，
也必须同时伪造一份**真正达标的** `ErrorPattern`
与一份准许的 `PromotionDecision`。

### 4. 落库关：`ProposalService.create` 必须携带门禁结论

落库是整条链路上**唯一会留下东西**的一步，因此它是最后一道关。
它拒绝三件事：

| 拒的是什么 | 为什么它必须被拒 |
|---|---|
| 未授权的结论 | 最基本的：没授权就不能落库 |
| **张冠李戴**的结论 | 拿 A 模式的授权去写 B 模式的提案。少了这条，**一次真实授权可以被复用成任意多条提案**，而每条都带着一份看起来无懈可击的门禁记录 |
| **证据不一致** | 评审会**按 id 去查证**这些经验。提案引用的与门禁重查到的若不是同一批，评审查到的与门禁批准的不是一回事，而两边都不会察觉 |

**顺序是有意的**：先查提案自身的形状（是不是 `DRAFT`），
再查授权。反过来的话，"一条状态就不对的提案"会先撞上
"门禁结论与提案不匹配"——那是**另一件事**的报错，
而调用方会照着它去修门禁那一侧。**报错指向的问题必须是实际存在的问题。**

### 5. 门禁当时看到的，随事件一起落库

`improvement_proposal.created` 的负载里新增四个字段：
`gate_threshold` / `gate_weighted_count` / `gate_occurrence_count` /
`gate_data_quality`。

审计问题是"这条提案凭什么被放行"，而回答它需要的**不是**
"门禁存在过"，是**那一刻的计数与读取完整性**。事后重跑门禁
未必得到同样结果（经验会继续累积），因此这些数字只能随事件落库。

`gate_data_quality` 尤其重要：**"读到 3 条" 与 "读到 3 条、
另有 2 条读不回来"是强度不同的两次授权**——而那些读不回来的记录里
可能就有把门槛顶过去的那一条。

### 6. 为什么在 `application/` 而不是 `learning/`

`learning/` 是纯函数：给定输入产出输出，不碰 IO。
而门禁要做的事情恰恰是**读存储**。

把它放进 `learning/` 会让整个包不再纯粹，也会让
"`learning/` 不做任何 IO"这条**容易检查**的规则变成"基本不做 IO"——
而"基本"是没法测的。

### 7. 读取只有一处实现

`ExperienceReader` 由学习链路与门禁**共用**。

如果门禁自己写一份读取逻辑，两份代码迟早会在某个边界上分家
（比如一个过滤了无法解析的记录、另一个直接抛异常），
而分家的表现是"门禁算出的次数与链路算出的不一样"——
**两者都不报错，只是永远对不上。**

## 替代方案与取舍

| 方案 | 为什么没选 |
|---|---|
| 让生成器多查几遍（阶段 6 的修法） | 消费端打补丁，挡不住过期的证据，也挡不住直接的构造 |
| 给 `GateVerdict` 加签名 / HMAC | V0.1 是单进程、无密钥管理。**为进程内防伪引入密钥**会把一个"代码组织问题"变成一个"密钥轮换问题"，而它防的是同一进程里的代码 |
| 把门禁做进数据库触发器 | 门槛是**策略**（权重、门槛值），不是数据完整性约束；放进数据库会让策略变更变成迁移 |
| 干脆让 `ProposalService.create` 自己重查 | 那会让落库方同时承担"写入"与"重新裁决"，而它的职责边界会变得无法描述 |

---

## 影响

- `ProposalService.create` 的签名新增必填参数 `verdict: GateVerdict`——
  **所有旧的调用点都会在类型层失败**，这是有意的：它们都是绕过门禁的调用；
- `LearningService` 重写：它自己扫一遍是**待办清单**，
  门禁扫一遍才是**授权**；两者用同一个读取器与同一份权重表。
  两处门槛/权重不一致时，症状是"链路每次都说发现了 N 个模式，
  却一条提案也没有"——那是个不会报错的故障模式，
  因此构造器默认从门禁取门槛与权重；
- 提案的生成输入是**门禁重算并授权过的**那份模式，
  不是链路自己扫出来的那份。§二.14 要求的"不信任传入的裁决"
  在生成这一步也成立：**那份裁决压根没有传进来过**；
- `tests/helpers.py::seed_learning_evidence` 因此必须存在——
  它让"先造一条提案再测它的生命周期"重新可行，
  但走的是真实链路（三个回合 → 三条经验 → 三条纠正 → 一次运行）。
  **它的使用边界写在函数文档里**，并且**不得**用于学习链路或
  阶段 6.5 §七 的黑盒验收；
- **残余风险**：门禁每次复核都要全量读取事件流，代价随历史线性增长。
  V0.1 的经验总量以百计，这不是问题；阶段 7 接入评测后
  若经验量上升到需要分页，读取器需要一个按 `(错误类别, 情境签名)`
  的索引——那时改的是 `ExperienceReader`，门禁一行不用动。
