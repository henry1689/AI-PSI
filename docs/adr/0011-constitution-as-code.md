# ADR-0011：认知宪法即代码

- **状态**：已接受
- **日期**：2026-09-17
- **相关**：ADR-0005（策略不得自动生效）、`docs/cognitive_constitution.md`

## 背景

任务书第十四节列出了 20 条**认知不变量**，并明确要求：

> 必须把以下规则**实现为代码断言或自动测试，而不是只写文档。**

其中第 12 条是："认知宪法不能被学习模块修改。"
任务书还要求交付 `docs/cognitive_constitution.md`。

问题在于：一份 Markdown 文档**无法被测试**，也**无法被强制**。
"宪法不能被修改"如果只写在文档里，就只是一句愿望——
任何一次不经意的编辑都能悄悄改变它，且没有任何机制会报警。

## 决策

**宪法以代码常量形式落实，配套不变量测试；Markdown 只是它的说明书。**

### 1. 代码是唯一真相来源

`src/ai_psi/cognition/constitution.py` 定义：

- **受保护的宪法常量**（如 `MAX_AUTOMATIC_MEMORY_TYPES`、
  `FORBIDDEN_MEMORY_CONTENT_CLASSES`、`EPISTEMIC_INVARIANTS`）
- **不变量断言函数**，供领域逻辑在运行时调用
- **`CONSTITUTION_VERSION`**，与 `EntityMetadata.schema_version` 协同

`docs/cognitive_constitution.md` 逐条解释**为什么**这些规则存在，
但**不重复定义**具体数值——避免两处定义漂移。

### 2. 不可变性由类型系统保证

宪法常量使用 `Final` 与不可变容器（`frozenset` / `tuple`），
模块级提供 `__getattr__` 守卫，任何试图在运行时修改的代码路径
都会抛出 `ConstitutionViolationError`。

### 3. 修改宪法 = 修改代码 = 走代码评审

这是本决策的核心：**让宪法变更成为一次显式的、可追溯的、需要人评审的动作。**

- 学习模块（`learning/`）**在依赖上不 import 宪法模块的可变部分**，
  只允许读取；
- 任何对 `constitution.py` 的修改都会出现在 git diff 中，
  与"改代码"享有同样的可见性；
- **不存在**任何配置文件、环境变量或数据库字段能覆盖宪法常量。

### 4. 不变量测试

`tests/unit/test_constitution.py` 逐条覆盖任务书 §14 的 20 条不变量中
可在纯领域层验证的部分（其余依赖数据库的不变量在阶段 2/5 补充）。

## 替代方案与取舍

| 方案 | 为什么不选 |
|---|---|
| 只写 Markdown 文档 | 不可测试、不可强制——正是本 ADR 要解决的问题 |
| 宪法放数据库表 | 数据库可被应用代码修改，"不能被修改"的保证更弱，且引入启动顺序依赖 |
| 宪法放配置文件（YAML/JSON） | 配置的本意就是"可改"；且环境变量覆盖会让宪法在不同机器上不同 |
| 用代码 + 运行时断言但不写测试 | 断言只覆盖被执行的路径，未执行的规则不会被发现 |

## 影响

- `constitution.py` 属于**高变更敏感度**文件——修改它应当触发特别关注。
- 学习模块（阶段 6）在设计上就**没有权限**触碰宪法；
  这将在阶段 6 以导入依赖测试的形式固定下来。
- `docs/cognitive_constitution.md` 需要与代码保持同步，
  但不是真相来源——两者不一致时**以代码为准**。
- 这为"系统不能自行改变认知宪法"提供了**可执行**的保证，
  而不只是文档承诺。
