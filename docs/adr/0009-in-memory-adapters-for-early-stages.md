# ADR-0009：早期阶段使用内存适配器

- **状态**：已接受
- **日期**：2026-09-17
- **相关**：ADR-0001（架构风格）、ADR-0004（记忆策略）

## 背景

**这是一处任务书内部的阶段依赖倒挂。**

任务书第十八节的阶段划分：

- **阶段 3「Mock LLM 和认知流水线」** 验收要求：**场景 A～J 全部通过**；
- **阶段 5「长期记忆」** 才交付：Memory Repository、pgvector 检索、
  WritePolicy、冲突/过期/取代、用户纠正。

但场景清单里有两个场景**必须依赖记忆系统**：

- **场景 F（用户纠正长期记忆）**：要求旧记忆被 superseded、新偏好生效、
  旧偏好保留纠错痕迹但不默认检索；
- **场景 J（用户隔离）**：要求检索完全隔离、不发生交叉引用。

也就是说，阶段 3 的验收条件在阶段 5 的交付物上，无法按字面顺序完成。

## 决策

**阶段 3 用内存适配器实现记忆相关 Port，阶段 5 替换为 PostgreSQL + pgvector 实现，
场景测试代码全程不变。**

具体做法：

1. 在阶段 3 定义 `MemoryRepository`、`MemoryRetriever`、`VectorIndex` 等 **Protocol（Port）**；
2. 提供 `InMemoryMemoryRepository` 等**内存实现**，行为语义与最终实现一致：
   - 强制 `user_id` 作用域
   - 支持 `SUPERSEDED` / `DISPUTED` 状态且默认不返回
   - 支持删除并传播到内存索引
   - 支持 `supersedes_id` 版本链
3. 场景测试**只依赖 Port**，通过依赖注入拿到具体实现；
4. 阶段 5 新增 `PostgresMemoryRepository`，**同一套场景测试换个 fixture 即可复用**；
5. 阶段 5 必须额外增加针对 pgvector 的集成测试（向量索引同步删除等），
   但**场景 A–J 本身不重写**。

**内存实现必须满足与真实实现相同的语义契约。**
它不是"简化版"——作用域隔离、取代失效、删除传播这三条不变量的断言
在内存实现上同样必须通过。否则阶段 5 的替换会暴露行为差异，
而那些差异会在最不该出问题的时候出现。

## 替代方案与取舍

| 方案 | 为什么不选 |
|---|---|
| 调整阶段顺序：先做阶段 5 再做阶段 3 | 违反任务书既定的阶段划分；且认知流水线的数据模型尚未稳定时做记忆存储，返工风险更高 |
| 阶段 3 跳过场景 F/J，留到阶段 5 | 直接违反阶段 3 的验收条件"场景 A～J 全部通过" |
| 阶段 3 就让场景测试连 PostgreSQL | 阶段 3 的验收要求是"不使用外部 API 也能完整运行"，且会把 DB 依赖引入认知流水线测试，拖慢反馈循环 |
| 用 SQLite 做早期存储 | 任务书明确要求"避免 SQLite 行为差异"，且 V0.1 不支持 SQLite（ADR-0007 的 URL 校验会直接拒绝） |

## 影响

- **Port 的设计必须在阶段 3 就定好**——这是本决策的主要风险。
  若 Port 设计不当，阶段 5 会需要改接口，从而波及场景测试。
  缓解：Port 的接口形状直接依据任务书 §10 的记忆操作清单设计，不自创语义。
- 内存适配器需要与真实实现共享同一套**契约测试**（同一组测试跑两个实现），
  这是保证"行为一致"的唯一可靠手段。
- 同样的问题也存在于其他跨阶段依赖，一并采用此模式：
  - **事件存储**（阶段 2 交付）在阶段 3 的流水线测试中同样可先用内存实现；
  - **向量检索**在阶段 3/4 完全不需要真实 embedding，用内存索引即可。
- 此决策同时降低了阶段 3 的开发阻力：可以在零数据库、零外部 API 的情况下
  完成整个认知流水线的开发与调试。
