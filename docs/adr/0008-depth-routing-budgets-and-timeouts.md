# ADR-0008：深度路由、认知预算与状态超时

- **状态**：已接受
- **日期**：2026-09-17
- **相关**：ADR-0010（元认知决策）、`docs/state_machine.md`

## 背景

任务书 §七要求 D0–D4 深度路由，§13.1 给出 `CognitiveBudget` 的默认值，
§6.3 要求"每个状态有超时"。

**但任务书没有给出：**
- 各级深度的具体预算差异（只说"允许按 D0～D4 配置不同预算"）；
- 任何一个状态的超时数值；
- 元认知模型调用是否计入 `max_model_calls`。

这三处是缺口，需要给出可执行的默认值。

## 决策

### 1. 路由以确定性规则优先

```python
def route_depth(inp: DepthRoutingInput) -> CognitiveDepth
```

评估顺序（短路，先命中先返回）：

| 条件 | 结果 |
|---|---|
| 用户显式指定 `user_requested_depth` | 采纳（但受预算上限约束，见下） |
| 简单事实且证据充分 | **D0** |
| 需要解释或比较 | **D1** |
| 多个合理解释，或证据冲突 | **D2** |
| 涉及长期关系、社会结构或价值选择 | **D3** |
| 用户明确提出哲学问题，或存在根本框架冲突 | **D4** |

**模型只能提出深度建议，最终由代码根据预算与规则确定。**

**硬约束：禁止为了让回答看起来更深刻而自动提升到 D4。**
只有当输入中确实存在价值冲突或框架性冲突时才允许 D4。

**预算降级规则**：若 `available_budget` 不足以支撑 `user_requested_depth`
的必需模块，则**降级到可支撑的最高深度**，并在响应中显式说明降级原因——
而不是悄悄超出预算，也不是直接拒绝。

### 2. 各级深度的预算表

| 预算项 | D0 | D1 | D2 | D3 | D4 |
|---|---|---|---|---|---|
| `max_model_calls` | 3 | 5 | 8 | 11 | 12 |
| `max_metacognitive_loops` | 0 | 1 | 2 | 2 | 2 |
| `max_hypotheses` | 1 | 2 | 4 | 4 | 4 |
| `max_retrieved_memories` | 5 | 10 | 15 | 20 | 20 |
| `max_context_tokens` | 4 000 | 8 000 | 16 000 | 24 000 | 32 000 |
| `max_duration_seconds` | 15 | 30 | 60 | 90 | 120 |

模块启用矩阵：

| 模块 | D0 | D1 | D2 | D3 | D4 |
|---|---|---|---|---|---|
| 检索 / 表达 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 已知未知 / 简单逻辑 | — | ✓ | ✓ | ✓ | ✓ |
| 假设 + 反证 + 替代解释 | — | — | ✓ | ✓ | ✓ |
| 概念分析 | — | — | 可选 | ✓ | ✓ |
| 辩证分析（价值与视角） | — | — | — | ✓ | ✓ |
| 哲理框架分析 | — | — | — | — | ✓ |

（对应任务书 §6.3：D0/D1 可跳过哲理分析；D2 以上才默认启用替代假设；
D3 以上启用价值和视角分析；D4 启用哲理框架分析。）

### 3. 元认知模型调用计入 `max_model_calls`

**决策：计入。**

理由：若不计入，`max_model_calls` 就不再是真实的成本上限，
预算也就失去了"防止无界花费"的意义。元认知的模型层检查
（迎合风险、确认偏差、抽象逃逸等）每次调用消耗 1 个单位。

`max_metacognitive_loops` 独立计数，限制的是**循环轮数**而非调用次数，
两者共同约束：最多 2 轮，且每轮消耗的调用数不得超过剩余预算。

### 4. 状态超时表

| 状态 | 超时（秒） | 超时后行为 |
|---|---|---|
| `CREATED` | 5 | → `FAILED` |
| `TRIAGING` | 15 | → `FAILED` |
| `FRAMING` | 30 | → `FAILED` |
| `RETRIEVING` | 45 | → `FAILED`（保留已写入事件） |
| `ANALYZING` | 60 | → `FAILED` |
| `DELIBERATING` | 60 | → `FAILED` |
| `METACOGNITIVE_REVIEW` | 30 | → 强制 `STOP` 并进入 `SYNTHESIZING` |
| `SYNTHESIZING` | 45 | → `FAILED` |
| `RESPONDING` | 30 | → `FAILED`（此时 Judgement 已持久化，可重试渲染） |
| `WAITING_FOR_EVIDENCE` | 无超时 | 由 `reopen_conditions` 或用户驱动 |

**关键约定：**
- 所有状态超时都受回合级 `max_duration_seconds` 的**总上限**约束。
- `METACOGNITIVE_REVIEW` 超时**不判失败**——它降级为"用现有材料合成答案"，
  这比丢失整个回合更符合用户利益，且不违反任何不变量。
- 超时进入 `FAILED` 时，**必须记录失败阶段与错误类别**（任务书不变量 20）。

## 替代方案与取舍

| 方案 | 为什么不选 |
|---|---|
| 全局单一预算配置 | 简单问题用 12 次模型调用是浪费，复杂问题被压缩则质量受损 |
| 元认知调用不计入预算 | 预算失去作为成本上限的意义，可能显著超出预期成本 |
| 完全让模型决定思考深度 | 违反任务书"模型只能提出深度建议"，且模型倾向过度思考 |
| 状态超时后一律 FAILED | 元认知超时判失败会丢弃已完成的分析工作，代价不成比例 |
| 请求深度超预算时直接报错 | 用户体验差且无必要；降级 + 显式说明是更好的默认 |

## 影响

- `CognitiveBudget` 需要 `for_depth(level)` 工厂方法，而不是若干全局常量。
- 深度路由与预算表都需要独立的单元测试，覆盖每条短路规则与降级路径。
- 超时表需要与状态机一起测试，确保"每个状态都有超时"可被断言验证。
- 指标 `average_model_calls_per_round` 与 `average_latency_per_depth`
  依赖此表做分组统计（任务书 §16.1）。
