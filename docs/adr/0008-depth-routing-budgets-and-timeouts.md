# ADR-0008：深度路由、认知预算与状态超时

- **状态**：已接受（**2026-09-18 按实测重新标定预算表**，见下方 §2 的修订说明）
- **日期**：2026-09-17
- **相关**：ADR-0010（元认知决策）、ADR-0015（阶段 3 实现决策）、`docs/state_machine.md`

## 背景

任务书 §七要求 D0–D4 深度路由，§13.1 给出 `CognitiveBudget` 的默认值，
§6.3 要求"每个状态有超时"。

**但任务书没有给出：**
- 各级深度的具体预算差异（只说"允许按 D0～D4 配置不同预算"）；
- 任何一个状态的超时数值；
- 元认知模型调用是否计入 `max_model_calls`。

这三处是缺口，需要给出可执行的默认值。

## 决策

### 1. 路由以确定性规则优先

```python
def route_depth(inp: DepthRoutingInput) -> CognitiveDepth
```

评估顺序（短路，先命中先返回）：

| 条件 | 结果 |
|---|---|
| 用户显式指定 `user_requested_depth` | 采纳（但受预算上限约束，见下） |
| 用户明确提出哲学问题，或存在根本框架冲突 | **D4** |
| 涉及价值选择，且价值冲突显著 | **D3** |
| 涉及长期关系、社会结构或人生选择 | **D3** |
| 存在多个合理解释 | **D2** |
| 高可信材料之间存在冲突 | **D2** |
| 简单事实但措辞歧义显著 | **不停留在 D0** |
| 简单事实且证据充分 | **D0** |
| 需要解释或比较 | **D1** |
| 无强信号 | **D1** |

> ⚠️ 上表的顺序在阶段 3 实现时**相对阶段 0 的初版做了调整**：
> 深层信号先判，浅层信号后判。
> 初版把"简单事实 → D0"排在前面，结果是
> "看起来像事实问题的价值冲突问题"会被压到 D0。
> 深层优先更符合"不得为了省事而降低分析深度"的取向。

**模型只能提供深度信号，最终由代码根据预算和规则确定。**

**硬约束：禁止为了让回答看起来更深刻而自动提升到 D4。**
只有当输入中确实存在价值冲突或框架性冲突时才允许 D4。
`tests/unit/test_orchestrator_and_depth.py` 里有一条用例专门验证
"把一切都标成 very_high 也不会升到 D4"。

**预算降级规则**：若 `available_budget` 不足以支撑 `user_requested_depth`
的必需模块，则**降级到可支撑的最高深度**，并在响应中显式说明降级原因——
而不是悄悄超出预算，也不是直接拒绝。

### 2. 各级深度的预算表

> 🔴 **2026-09-18 修订（阶段 3 完成）**
>
> 下表 `max_model_calls` 一列是**按实测的模块成本重新标定**的，
> 与原值不同。阶段 1 写下的 3/5/8/11/12 是估算；
> 阶段 3 实现模块矩阵后逐档核算出真实值。
>
> 精确的不变式（由 `tests/unit/test_orchestrator_and_depth.py` 断言）：
>
> ```
> max_model_calls ≥ 标称模块数 + (max_metacognitive_loops − 1) × 2
> ```
>
> **差一次调用就意味着反刍检测永远等不到第二次复核来比较两轮判断**，
> 而任务书 §13.3 的防反刍正是建立在"连续两轮"之上。
>
> 完整推导见 ADR-0015 §2。

| 预算项 | D0 | D1 | D2 | D3 | D4 |
|---|---|---|---|---|---|
| `max_model_calls`（**修订**） | **4** | **6** | **10** | **12** | **13** |
| ~~原值~~ | ~~3~~ | ~~5~~ | ~~8~~ | ~~11~~ | ~~12~~ |
| 标称模块数 | 4 | 6 | 8 | 10 | 11 |
| 额外循环预留 | 0 | 0 | 2 | 2 | 2 |
| `max_metacognitive_loops` | 0 | 1 | 2 | 2 | 2 |
| `max_hypotheses` | 1 | 2 | 4 | 4 | 4 |
| `max_retrieved_memories` | 5 | 10 | 15 | 20 | 20 |
| `max_context_tokens` | 4 000 | 8 000 | 16 000 | 24 000 | 32 000 |
| `max_duration_seconds` | 15 | 30 | 60 | 90 | 120 |

任务书 §13.1 的默认值 12 是**全局默认**；§13.1 同时明确允许按 D0～D4 配置不同预算，
因此 D4 的 13 不构成偏差。

模块启用矩阵：

| 模块 | D0 | D1 | D2 | D3 | D4 |
|---|---|---|---|---|---|
| 关切检测 / 问题框定 / 上下文 / 判断合成 / 回答渲染 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 已知未知 / 简单逻辑 | — | ✓ | ✓ | ✓ | ✓ |
| 假设 + 反证 + 替代解释 | — | — | ✓ | ✓ | ✓ |
| 因果分析 | — | — | ✓ | ✓ | ✓ |
| 概念分析 | — | — | — | ✓ | ✓ |
| 辩证分析（价值与视角） | — | — | — | ✓ | ✓ |
| 哲理框架分析 | — | — | — | — | ✓ |

（对应任务书 §6.3：D0/D1 可跳过哲理分析；D2 以上才默认启用替代假设；
D3 以上启用价值和视角分析；D4 启用哲理框架分析。）

### 3. 元认知模型调用计入 `max_model_calls`

**决策：计入。**

理由：若不计入，`max_model_calls` 就不再是真实的成本上限，
预算也就失去了"防止无界花费"的意义。元认知的模型层检查
（迎合风险、确认偏差、抽象逃逸等）每次调用消耗 1 个单位。

`max_metacognitive_loops` 独立计数，限制的是**循环轮数**而非调用次数，
两者共同约束：最多 2 轮，且每轮消耗的调用数不得超过剩余预算。

**补充（阶段 3）**：一轮**额外**循环的代价是 **2 次调用**
（重新合成判断 + 再次元认知复核）。
`ANALYZING` 阶段的分析器**不重跑**——那是 `CHANGE_METHOD` 的路径，不是默认路径。
额外一轮之后仍需保留 **1 次**（回答渲染）。

### 4. 状态超时表

| 状态 | 超时（秒） | 超时后行为 |
|---|---|---|
| `CREATED` | 5 | → `FAILED` |
| `TRIAGING` | 15 | → `FAILED` |
| `FRAMING` | 30 | → `FAILED` |
| `RETRIEVING` | 45 | → `FAILED`（保留已写入事件） |
| `ANALYZING` | 60 | → `FAILED` |
| `DELIBERATING` | 60 | → `FAILED` |
| `METACOGNITIVE_REVIEW` | 30 | → 强制 `STOP` 并进入 `SYNTHESIZING` |
| `SYNTHESIZING` | 45 | → `FAILED` |
| `RESPONDING` | 30 | → `FAILED`（此时 Judgement 已持久化，可重试渲染） |
| `WAITING_FOR_EVIDENCE` | 无超时 | 由 `reopen_conditions` 或用户驱动 |

**关键约定：**
- 所有状态超时都受回合级 `max_duration_seconds` 的**总上限**约束。
- `METACOGNITIVE_REVIEW` 超时**不判失败**——它降级为"用现有材料合成答案"，
  这比丢失整个回合更符合用户利益，且不违反任何不变量。
- 超时进入 `FAILED` 时，**必须记录失败阶段与错误类别**（任务书不变量 20）。

### 5. 预算耗尽的处理（阶段 3 补充）

**可选模块**在预算不足时被**跳过并记录**（`RoundOutcome.skipped_steps`），
而不是让回合失败。被跳过的步骤必须可见——静默消失等于"看起来全跑了"。

**强制模块**（判断合成、回答渲染）始终有额度保留
（`MANDATORY_TAIL_CALLS = 2`）。检索阶段的保留额度随回合推进收缩：
分析阶段同时留出判断 + 元认知 + 渲染，判断一旦产出就只剩渲染。

## 替代方案与取舍

| 方案 | 为什么不选 |
|---|---|
| 全局单一预算配置 | 简单问题用 13 次模型调用是浪费，复杂问题被压缩则质量受损 |
| 元认知调用不计入预算 | 预算失去作为成本上限的意义，可能显著超出预期成本 |
| 完全让模型决定思考深度 | 违反任务书"模型只能提出深度建议"，且模型倾向过度思考 |
| 状态超时后一律 FAILED | 元认知超时判失败会丢弃已完成的分析工作，代价不成比例 |
| 请求深度超预算时直接报错 | 用户体验差且无必要；降级 + 显式说明是更好的默认 |
| 浅层信号优先判定（阶段 0 初版） | 会把"看起来像事实问题的价值冲突"压到 D0 |
| 保持阶段 1 的估算预算 | 会逼着编排器在运行期少跑模块，反刍检测因此永远不触发 |
| 预算不足时让回合失败 | 少做一次分析远好过拿不出结论；且失败会丢掉用户的问题 |

## 影响

- `CognitiveBudget` 需要 `for_depth(level)` 工厂方法，而不是若干全局常量。
- 深度路由与预算表都需要独立的单元测试，覆盖每条短路规则与降级路径。
- 超时表需要与状态机一起测试，确保"每个状态都有超时"可被断言验证。
- 指标 `average_model_calls_per_round` 与 `average_latency_per_depth`
  依赖此表做分组统计（任务书 §16.1）。
- **`Settings` 不再携带 `budget_max_*` 字段**：它们是死配置（无读取方），
  阶段 3 已删除。预算的权威表只有 `_BUDGET_BY_DEPTH` 一处（ADR-0015 §2）。
  环境变量形式的按深度覆盖仍未提供，登记于 `docs/risks.md` R16。
