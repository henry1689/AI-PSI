# ADR-0004：记忆策略

- **状态**：已接受
- **日期**：2026-09-17
- **相关**：ADR-0002（事件模型）、ADR-0012（范围边界）、`docs/security.md`

## 背景

任务书第十节规定了长期记忆的写入流程、可自动写入与不可自动写入清单、
用户纠正与记忆删除的要求。第十四节把其中若干条列为**必须实现为代码断言**的不变量：

- 被取代的记忆不能作为默认有效记忆返回
- 记忆检索必须遵守 `user_id` 作用域
- 删除的记忆不得继续出现在向量检索结果中

这里的风险最高：记忆一旦污染，会持续影响后续所有认知回合。

## 决策

**核心原则：写入靠白名单，读取靠作用域，纠正是版本链，删除是传播。**

### 1. 写入：默认拒绝的白名单模型

所有记忆写入必须经过 `WritePolicy`，且**默认拒绝**——
只有明确命中以下白名单才可**自动批准**：

| 可自动写入 | 条件 |
|---|---|
| 称呼偏好 | 用户在当前系统中**明确确认**，且非敏感 |
| 认知回合事件摘要 | 回合已完成，仅含结构化摘要 |
| 系统自身的错误记录 | 属于系统可靠性范畴 |
| 任务偏好 | **不含**稳定人格推断 |
| 候选经验 | 已标记为暂定 |

**必须拒绝或等待用户确认**（任务书 §10.3）：
心理诊断、政治/宗教/健康等敏感推测、用户稳定人格结论、未经确认的长期目标、
从一次互动推断的价值观、第三方隐私、模型自由联想、未经核验的事实、
完整隐藏思维链、系统生成的通用策略。

**特别澄清：模型永远不能直接写数据库**（任务书原则 17）。
记忆写入只能由 `application/memory_service.py` 发起。

### 2. 读取：作用域是硬隔离

检索**必须**带 `user_id` 条件，这不是过滤优化而是安全边界。
任何绕过作用域的检索路径都视为缺陷（属性测试覆盖，见任务书 §15.2）。

### 3. 纠正：版本链，不覆盖

用户纠正时：
1. 创建 `user.correction.received` 事件；
2. 旧记忆标记为 `SUPERSEDED` 或 `DISPUTED`；
3. 创建新版本记忆，`supersedes_id` 指向旧版本；
4. 更新向量检索的有效状态；
5. **旧版本保留但默认不返回**，保留纠错痕迹与审计轨迹。

禁止"直接改旧记忆内容"——那会抹掉审计证据。

### 4. 删除：必须传播

删除至少提供：按 `memory_id` 删除、按 `user_id` 导出与删除、逻辑删除、
向量索引同步删除、摘要重新生成标记、删除事件记录。

**审计事件不得保留被删除内容正文**——只记录"某 id 于某时刻被删除"这一事实。

### 5. 冲突检测

新记忆与既有记忆矛盾时，写入 `contradicts_ids`，**不强行合并**。
冲突本身是有价值的信息，应当在后续认知回合中被显式呈现（场景 E）。

## 替代方案与取舍

| 方案 | 为什么不选 |
|---|---|
| 让模型决定什么值得记（LLM 自主记忆） | 直接违反任务书 §10.3 与不变量 10、13；记忆污染不可控 |
| 黑名单模型（默认允许，列举禁止） | 漏网风险高；记忆污染的代价远大于漏记的代价 |
| 物理删除取代逻辑删除 | 会摧毁审计轨迹，违反"保留审计轨迹"要求；但**必须**传播到向量索引 |
| 单一记忆表无版本链 | 无法满足"用户纠正必须生成新版本"的不变量 5 |

## 影响

- `MemoryProposal` 是一个独立的中间态，不是 `Memory` 的草稿——它有自己的审批事件。
- 向量检索必须与主表的状态保持同步，删除/取代必须同时作用于两者（阶段 5 关键测试点）。
- 记忆写入拒绝率本身是评测指标之一（任务书 §16.1），用于观测策略是否过严或过松。
- 阶段 3 用内存适配器实现该接口以支撑场景 F/J，阶段 5 换成 PostgreSQL + pgvector，
  **场景测试代码不变**（ADR-0009）。
