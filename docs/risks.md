## 1. 认知风险（最高优先级）

这类风险的特殊之处：**后果是累积的**。
一次错误回答只影响一次交互；一次错误的记忆写入会持续影响此后所有回合。

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| **R1** | **记忆污染**：错误信息被写入长期记忆 | 持续污染后续所有回合，且用户难以察觉 | WritePolicy 白名单 + 默认拒绝（ADR-0004）；`memory_write_rejection_rate` 作为观测指标 |
| **R2** | **跨用户泄漏** | 隐私事故，不可撤销 | `user_id` 作用域为必填参数（无默认值）；属性测试断言（硬指标 = 0） |
| **R3** | **删除未传播到向量索引** | "已删除"的记忆仍可被检索出来 | 删除必须同时作用于主表与索引；阶段 5 专项测试 |
| **R4** | **过度自信**：回答比内部判断更确定 | 误导用户，且违反不变量 7 | `EpistemicAction` → 语气档位映射 + 渲染后一致性校验 |
| **R5** | **迎合**：为让用户满意而放弃分析 | 系统退化为奉承机器 | 场景 D 专项；元认知的 `user_pleasing_bias_risk` 检查 |
| **R6** | **把用户赞同当事实验证** | 不变量 4 被绕过 | 反馈路径**没有**"置为 VERIFIED"的入口 |
| **R7** | **抽象逃逸**：用抽象语言掩盖事实不足 | 回答看似深刻实则空洞 | 元认知的 `abstraction_escape_risk`；§9.9 明确禁止 |
| **R8** | **虚假平衡**：机械地"双方都有道理" | 失去判断力 | §9.8 明确禁止；`DialecticalAnalysis` 要求给出真实张力 |
| **R9** | **提案门槛被绕过**：单次经验升级为全局策略 | 违反不变量 10 | 门槛以常量实现并测试；`proposal_false_promotion_rate` 硬指标 = 0 |

## 2. 工程风险

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| **R10** | **Prompt 散落在业务代码中** | 无法测试、版本化、回滚 | Prompt 契约规范（`docs/prompt_contracts.md`） |

## 3. 环境与工具链风险

| # | 风险 | 状态 | 处理 |
|---|---|---|---|
| **R17** | 本机 `make` 缺失 | ✅ 已解决 | winget 装 GNU Make 4.4.1 |
| **R18** | 无法直连 Docker Hub | ✅ 已解决 | `AI_PSI_PG_IMAGE` 可覆盖；本地走镜像源 |
| **R19** | ruff 格式化 Markdown 代码块 | ✅ 已解决 | 排除 `**/*.md`（ADR-0007） |
| **R20** | Python 3.13 依赖 wheel 缺失 | ✅ 未发生 | 实测全部依赖有 wheel；若发生则回退 3.12（ADR-0007） |
| **R21** | shell 的 `VIRTUAL_ENV` 指向全局 3.11 | ⚠️ 仅噪声 | uv 自动忽略并使用项目 `.venv`，不影响结果 |
| **R22** | 网络不稳定（Docker Hub / SourceForge 均曾超时） | ⚠️ 观测中 | 重试；关键依赖提前下载 |
| **R28** | **Windows 事件循环不被 psycopg 异步支持** | ✅ 已解决 | `asyncio_compat` 统一处理；pytest 需 hook + 全局策略**双保险**（ADR-0014） |
| **R29** | **`.ini` 文件被 locale 编码读取** | ✅ 已解决 | `alembic.ini` 保持纯 ASCII（踩了两次：中文注释 + 破折号）（ADR-0014） |
| **R30** | **集成测试误连开发库并 TRUNCATE** | ✅ 已缓解 | 测试库独立派生 + 配置层拒绝两者相同（ADR-0014） |
| **R31** | 测试引擎池化连接跨事件循环复用 | ✅ 已解决 | 测试引擎用 `NullPool`（ADR-0014） |
| **R32** | **反刍检测只有词面精度** | 改写过的同一论点不会被判为重复，导致多跑一轮 | 刻意保守：漏判由循环上限与预算兜住，误判则会让系统提前放弃分析。语义级检测待阶段 5 向量检索。`tests/unit/test_reliability.py` 有一条用例把这个局限**钉死为预期行为** |
| **R33** | **预算表与模块矩阵漂移** | 二者住在不同模块，改一处忘一处，"循环永不超预算"在运行期破功 | 三张表（预算 / 标称调用数 / 模块矩阵）的一致性由 `tests/unit/test_orchestrator_and_depth.py` 断言 |
| **R34** | **记忆写入与事件写入不同事务** | 极端情况下可能出现"记忆改了但事件没写" | ✅ **阶段 5 已闭合**：记忆仓储纳入 `UnitOfWork`，四步同事务。由 `TestAtomicity`（注入一个写事件必失败的存储）作为**直接证据**（ADR-0017 §3） |
| **R36** | **推理 token 吃掉输出预算** | 截断 → 分析丢失甚至回合失败 | 推理预留按实测标定（16384）；截断在解析前判定并给出可操作的错误；可选模块降级而非失败。**根治靠提示词约束输出规模，需评测支撑（阶段 7）** |
| **R37** | **真实模型不按 Schema 说话** | 结构化解析失败 | 提取修复（去代码块 / 括号配平扫描）+ JSON 模式 + 有限重试；失败时可选模块降级并留痕。**实测：真实回合中 `logical_analyzer` 的失败几乎全部是截断而非格式** |
| **R38** | **单回合成本远高于直觉** | D4 实测 ~21k 输入 + ~33k 输出（其中推理 ~22k） | 已量化记录（ADR-0016 §10）；预算表限制调用**次数**，但无法限制单次生成长度——这是阶段 7 的评测对象 |
| **R39** | **同一个旋钮有两个默认值** | 改一个毫无效果，排查成本高 | 配置层默认改为 `None`（= 用 Provider 默认值）；`TestReasoningHeadroomPlumbing` 钉死，含 `0` 必须被当作合法配置 |
| **R40** | **V0.1 没有认证层** | `user_id` 由调用方声明，故意传入别人的 id 就能读到别人的记忆 | 作用域过滤防的是"代码写错导致的串号"，**不是恶意调用者**。边界写在 `api/routes/memories.py` 的模块文档里；认证不在 V0.1 范围内，阶段 8 的"已知限制"必须包含它 |
| **R41** | **默认向量是词面的，不是语义的** | 同义改写匹配不上，用户会觉得"系统明明记过却想不起来" | `LocalHashingEmbedding` 的局限写在模块文档与 ADR-0017 §1；换 `openai_compatible` 即得真语义。**风险在于它看起来"能用"**——检索确实工作，只是召回范围比语义窄 |
| **R42** | **冲突阈值随向量空间漂移** | 换语义模型后 0.75 从"很接近"变成"随便两条都算"，线索变成噪音 | 阈值有明确文档标注"针对本地向量标定"，换 Provider 必须重新标定；线索只进审计、不驱动任何有代价的动作，因此漂移的后果是**噪音而非错误判断** |
| **R43** | **换向量 Provider 后旧记忆静默失效** | 检索只比对同版本向量，换 Provider 后**旧记忆一条都检索不到**，且不报任何错 | 这是刻意的（比较两个不同语义空间的向量毫无意义），但必须可修：`MemoryService.reindex` 显式重建；`test_only_matching_versions_are_retrieved` 复现这个状态 |
| **R44** | **向量维度是数据库列的固定属性** | 改了配置却忘了改迁移，写入会被 PostgreSQL 拒绝 | 维度写死在迁移里（用常量而非运行时配置，保证迁移可复现）；`test_stored_vector_has_the_migrated_dimension` 在真实库上核对；`OpenAICompatibleEmbedding` 对返回维度不符**明确失败** |
| **R35** | **提示词注入** | 用户内容里的三连反引号可以提前闭合数据块，把后续文字变成"指令" | 数据块内容经 JSON 编码后**额外转义反引号**；模板只允许 `{{input}}` 一个占位符；`tests/unit/test_prompt_registry.py` 有用例专门复现这个攻击 |

## 6. 需要持续关注的三个问题

1. **Port 设计**（R12）——✅ 阶段 3 已定型。
   `MemoryRepository` 的形状直接依据任务书 §10 的操作清单，未自创语义。
   阶段 5 的验证点是：换实现时**场景测试一行都不用改**。
2. **契约测试**（R13）——✅ 已建立并立刻证明了自己的价值
   （抓到两处 PostgreSQL 实现的不一致）。
   阶段 5 要做的是把记忆仓储接进 `tests/integration/test_contract_postgres.py`
   里预留的占位类，而不是新写一套。
3. **范围纪律**（R23）——每个阶段结束时仓库必须可运行；
   不可运行就不算完成。
4. **反刍检测的精度**（R32）——当前是词面相似度，只捕捉逐字重复。
   阶段 4 接入真实模型后这个局限已经暴露：真实模型的两次判断会改写措辞，
   因此阈值 0.85 实际上只能捕捉"逐字重复"。
   阶段 5 交付了向量检索的**能力**（`memory/retrieval.py`），但阈值仍是词面标定，
   且默认向量本身就是词面的（R41）——换成外部语义向量之前，
   用它做语义级检测没有意义。**阶段 7 应结合评测数据重新标定阈值**，
   并在此之前决定要不要换向量 Provider。
5. **单回合成本**（R38）——D4 回合实测约 21k 输入 + 33k 输出，其中推理占 22k。
   预算表限制的是**调用次数**，管不住**单次生成的长度**。
   阶段 7 的评测应把"每个任务的合理输出规模"一并标定，
   并把结果反馈到提示词模板里（限定列表长度与条数）。
