## 二、🔴 修订后的**阶段 6 完成定义**

这是本阶段最重要的产出。原定义里有三条**按证据不成立**，
必须降级——降级不等于"没做"，而是"做到的与声称的不是一回事"。

### 2.1 成立（有 E3 级证据：真实 HTTP × 真实 PostgreSQL + 反例）

| 能力 | 证据 |
|---|---|
| **提案永不自动生效** | 枚举 ⊆ 数据库且数据库 ⊆ 枚举的**双向**一致性测试 + 真实 PG 上 4 状态 × 4 参数的拒绝实测 + 状态图模型化测试 + AST 扫描 |
| **回放可达，且一致性告警会被读到** | 真实 HTTP 走 `ReplayService`；`differs_from_projection` 必填，且回放状态与实时投影对得上 |
| **离线评测：lower-is-better 指标上升判为退化** | 真实 HTTP + 真实 PG + **默认 Mock**，反刍率 0.0 → 1.0 实测判退化；反向对照（无退化报 `false`） |

### 2.2 ⚠️ 降级一：**"三次同类错误 → DRAFT 提案"没有黑盒证据**

链路是**可达**的（CLI + `POST /learning/runs`，且必经 `ProposalGate`），
但 §八 评审 A 用默认配置实测：**每条经验的 `error_type` 都是 `None`**，
于是 `PromotionPolicy.decide` / `ProposalGenerator.generate`
**一次都不会被调用**。

> **准确的说法是"可达"，不是"会跑"。**

它的端到端证明至今仍在 `tests/scenarios/test_learning_chain.py`
（**内存 Harness + 脚本化 Provider**），而 §七 要的是黑盒。
评审 A 用一次脚本化 Mock + 真实 HTTP + 真实 PG 手工跑通过
（`status=draft`、`supporting_experience_count=3`），
**但那一次没有固化成用例**——按矩阵填写规则第 5 条，手工验证不是证据。

**阶段 7 待办**：把评审 A 那次手工复现固化成黑盒用例；
或让默认 Mock 能产生可归因的回合。

### 2.3 ⚠️ 降级二：**§七.5/7/8 与 §七.14 没有等价物**

* §七.5/7/8（重复处理不冒充独立经验）：**没有"重新处理某个回合"的端点**，
  经验只在回合收尾产出。落点在单元层（`test_pattern_detector.py`）。
* §七.14（并发只允许一个成功）：反馈**不是幂等的单次写入**，
  同一回合的两条反馈是两件事、都该成功。系统里唯一"只允许一个成功"的
  并发写入是**幂等键占位**，它已单独覆盖。
  问题是有条用例的名字一直说反话（`..._only_one_succeeds` 断言两条都 201），
  已改名并写明缺口。

### 2.4 ⚠️ 降级三：**进程内防伪做不到，也不假装做到**

ADR-0022 §3 曾称"第二道防线"是"必须同时伪造达标的 `ErrorPattern`
与准许的 `PromotionDecision`"。评审 B 实测**证伪**：
`dataclasses.replace`（把 `_token` 原样带过来，且是正常库调用）、
`object.__new__`、`copy` / `deepcopy` / `pickle` / 子类化——全部绕过；
而那两个"必须伪造"的对象是**零校验的裸 frozen dataclass**。

**修订后的定义**：这道防线挡的是**随手构造**与**经 API 写入**，
不是"能在进程内执行任意 Python 的主体"。后者**已经越过了本系统的边界**。
